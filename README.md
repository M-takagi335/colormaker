# 絵の具混色ゲーム

赤・青・黄・白・黒の絵の具をチューブから出し、パレット上で混ぜて見本の色を作るブラウザーゲームです。制限時間、絵の具の使用量制限、お題数の上限はありません。ゲーム名は仮タイトルです。

## 遊び方

1. チューブを短く押すと少量、長く押すと連続で絵の具が出ます。
2. パレットを指またはマウスでなぞり、絵の具の境目をまたいで混ぜます。途中で絵の具を足せます。
3. 2つの色見本を比べます。「作っている色」は、パレット全体が均一に混ざったときの色です。均一度のメーターで、パレットに残った色むらを確認できます。
4. 「完成」で採点します。結果画面から混色の続行、同じお題のやり直し、次のお題への移動ができます。

「元に戻す」で直前の操作を取り消せます。「リセット」で同じお題のパレットを空にし、「お題をスキップ」で次のお題へ進みます。「記録」に自己ベスト、平均、挑戦数、95点以上と100点の回数、過去に作った色が並びます。「設定」で効果音の音量とミュートを変更できます。

## 起動と公開

HTML、CSS、JavaScript、Canvas 2D、Pointer Events、Web Audio を使用しています。ビルド、外部サービス、ログインは不要です。ローカルではリポジトリのルートで次を実行し、ブラウザーで `http://localhost:8000/` を開きます。

```sh
python -m http.server 8000
```

GitHub Pages では、変更が `main` に入った後、リポジトリの **Settings → Pages** を開き、**Deploy from a branch** で **main / (root)** を選びます。すべてのゲーム資産を相対パスで参照しているため、プロジェクト用のサブパスで動作します。[GitHub Pages の公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## パレットの物理と描画

144×88 の格子で、各セルに5種類の顔料量を保持します。合計量が絵の具の厚みに相当します。ポインターの経路を補間し、接触した範囲の顔料を移動方向に配分します。移動距離、速さ、接触中心からの距離に応じて移送量と行き先が変わります。湿ったセル同士では同量を交換して色の筋を徐々に混ぜます。乾いた隣接セルにはこの交換を適用しません。境界への移送は端のセルに集め、各顔料は浮動小数点の演算誤差の範囲で保存します。

新しい絵の具はチューブ近くの別の場所に重ね、場所が埋まっている場合は接触範囲にある他色を縁へ押し出します。指を動かさないと混色は進みません。描画用の格子は物理の2倍の解像度で補間し、厚みの傾きから濡れたような光沢と陰影を求めます。描画は操作で変化したフレームだけ行い、背景タブでは停止します。

## 顔料モデルとお題

4つの有効反射帯域（赤、緑、青、橙）を使った Kubelka–Munk 近似です。顔料ごとの吸収係数 K と散乱係数 S を配合量で重み付けし、厚い塗膜の近似式 `R = 1 / (1 + K/S + √((K/S)² + 2K/S))` で反射率を求めます。反射帯域を線形 sRGB の各成分へ写し、sRGB の伝達関数を適用します。白は散乱が強く、黒は少量で反射率を下げます。同じ比率なら、混ぜる順番にかかわらず同じ代表色になります。

反射係数はゲーム向けに調整した値です。実測の分光データ、透過、塗膜の乾燥、絵の具の化学反応はモデル化していません。描画用の光沢は別に計算します。

お題の配合は、チューブの短押しの整数回数で再現できる量から生成します。鮮やかな組、白を加えた組、黒を加えた組、3原色を含む組の切り替えと、直前の色に近い候補の取り直しで変化をつけています。生成した sRGB 色だけを保存し、再読み込みで同じお題を復元します。

既存作の調査では、日替わりの減法混色パズルと、流体キャンバス上で顔料を混ぜる作品を確認しました。この実装では、チューブを絞る操作から局所混色、均一度を含む採点までを同じ顔料の格子でつなげています。[My Color Taste Paint Mixer](https://mycolourtaste.com/games/paint-mixer/) · [Color Mixer](https://github.com/mblode/color-mixer)

## 採点

- **色の一致度**は、sRGB を D65 の CIELAB に変換し、代表色と見本色の CIEDE2000 色差 ΔE₀₀ から `100 × exp(−ΔE₀₀ / 21)` で求めます。
- **混色の均一度**は、絵の具を含むセルの色と代表色の色差について、絵の具量で重み付けした二乗平均平方根 D から `100 × exp(−D / 10)` で求めます。
- **総合**は一致度80%、均一度20%の加重平均です。一致度＋8点と、72点＋均一度の28%を上限として適用します。完全一致かつ均一な場合は100点です。

採点には顔料の反射色を使用し、背景、陰影、光沢を除きます。色差の計算は [Sharma・Wu・Dalal の参照データ](https://hajim.rochester.edu/ece/sites/gsharma/ciede2000/) の事例で検証しています。

## 保存と制約

バージョン付きのブラウザー内保存に、現在のお題、顔料分布、採点履歴と集計、音量設定を保存します。顔料の Float32 配列はバイナリを Base64 化して保存し、混色途中の分布をそのまま復元します。操作中の保存は間隔を空け、操作終了とページ非表示時にも保存します。元に戻す履歴は現在のページで直近28操作分です。プライベートブラウジングやブラウザーの空き容量によっては保存が利用できません。

物理は指に追従する粘性の高いペーストを近似しています。操作直後に静止するため、長く流れ続ける液体や、絵の具がパレットから垂れる挙動は扱いません。描画のフレームレートは塗布面積と端末の性能に依存します。

外部ライブラリ、画像、音源、Web フォントは使用していません。チューブは CSS で描き、音は Web Audio で合成しています。アクセス解析はありません。

## テスト

Node.js 22 で `npm test` を実行します。自動テストは7件で、CIEDE2000、主要な混色、局所性、顔料保存、端の挙動、ランダム出題、保存と復元を検証します。

Chrome と Edge の Chromium 実ブラウザーテストは、ルートで `node scripts/browser-smoke.mjs . "<Chromium系ブラウザーの実行ファイル>"` を実行します。Chrome の既定の Windows インストール先を使う場合は引数を省略できます。仮のサブパス上で、チューブ5色、長押しの追加と停止、ドラッグ混色、元に戻す、再読み込み、採点、記録、設定、お題の維持と切り替え、390×700 のタッチ入力と誤スクロールの有無、JavaScript エラーを確認します。

iPhone と Android の実機、Safari、Firefox、長時間のフレームレートや音質、GitHub Pages 本番への公開後の動作は未確認です。
